# Queue Rail Micro-Interactions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the micro-interaction gaps in the SAT question number panel (`QuestionQueueRail.tsx` + `AuthoringSegmented.tsx` + `ModuleScopePicker.tsx`) per core micro-interaction principles (one purpose per motion, instant state over animation, feedback within ~150ms, static affordances over hover-reveal, reduced-motion parity) — with zero visual redesign and zero contract changes.

**Architecture:** Same strangler posture as the spine plan: `AuthoringWorkspace` stays the orchestrator and keeps owning `navigationError`, `isMutating`, cache invalidation, and all mutation hooks. Rail changes are presentational + local pending flags only. No backend, contract, validation-logic, route, or delivery-renderer changes. `handleQuickAnswerKey` (workspace lines ~651-700) is currently dead upstream of the rail (rail dropped its A–D quick-key buttons in an earlier slimming pass) — removed as dead code rather than rewired.

**Tech Stack:** React 19 + Tailwind v4 + shadcn/ui + Radix (`radix-ui`) + TanStack Query + existing `AuthoringConfirmDialog` / `AuthoringSegmented` primitives. No new dependencies. No `motion/react` additions — all feedback is instant state (disabled + `aria-busy`), never animation.
