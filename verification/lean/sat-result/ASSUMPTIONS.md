# Assumptions, unknowns and limitations

Each assumption names its owner, the code or DB anchor it rests on, how it was validated, and its criticality. The proofs are stated **under** these assumptions; none of them is a proved fact about the deployed system.

## Assumptions

| ID | Assumption | Owner / anchor | Validation | Criticality |
| --- | --- | --- | --- | --- |
| A-DB | There is one result row per attempt and provider, one module row per `(attempt, module)`, one response per `(module_attempt, exam_question)`, and one section row per `(result, section_key)`. The model's `Option Row`, `List DbRow` and keyed answer lookup rest on this. | Schema. `uq_assessment_result_attempt_provider` (0044, deduplicated by 0057). `module_attempt_identity` (0032 `uq_assessment_attempt_module`, renamed in 0047). `uq_module_attempt_question` and `uq_assessment_result_section` (0032). | `evidence/mysql-migrate.txt` (fresh DB migrated to 0085). `TestSATClassroomRawScoreReleasedOnceMySQL` under `-race` and a 20× soak (`evidence/mysql-result-flow.txt`, `mysql-result-soak.txt`). | Critical. It underpins SC-06, REL-1 and PAPER-2. |
| A-TX | `materializeSATResult` runs inside the seal transaction. The receipt, the result row and `classroomRaw` commit or abort together. `RepairClassroomResults` locks candidate rows (`FOR UPDATE OF ar`) and writes with a guarded `UPDATE … WHERE outcome_status='pending' AND release_status='pending'`. A failed score read keeps the receipt and leaves the row pending (TC-15). | `terminalization/service.go` `materializeSATResult` (`:965`), `classroomPendingSQL` (`:1526`), `RepairClassroomResults` (`:1532`). | Reviewed. `TestClassroomScoreFailureKeepsReceiptAndWithholds`, `TestRepairClassroomResults`, `TestSATV2SubmitAndTimeoutReconcileRaceWithProductionSealer` (MySQL, `-race`, 20× soak). | Critical. The model treats each of `submit`, `terminate` and `repair` as one atomic step. |
| A-RCPT | Each attempt has exactly one immutable terminal receipt. A later seal with a different outcome is refused with 409 (`OutcomeCompat` requires equality). `materializeSATResult` is only ever called with the receipt's own outcome. So a sealed **submitted** attempt is never terminated afterwards. | `attempt_terminalizations` immutability triggers (0056). `terminalization/service.go` `OutcomeCompat` (`:260`) and the conflict branch (`:505–525`). Repair replays `receipt.Outcome` (`:1514`). | `TestReceiptImmutabilityMySQL` and `TestSubmitVsTerminateCrossOutcomeConflicts` (`evidence/mysql-receipt.txt`). | High. It turns the model's `released_then_invalidated` into an unreachable production trace (L-2). |
| A-IMM | Once a module or attempt is closed, the server accepts no further answer for it. Every mutation goes through `ensureAttemptCanWorkTx`, which takes a `FOR UPDATE` lock on the attempt row and checks proctor/delivery status, plus the module-state lock. | `delivery/service.go` `ensureAttemptCanWorkTx` (`:1895`) and the active-module `FOR UPDATE` (`:1954`). This applies only to callers that use it, i.e. `TerminalizeInTx` paths. | Reviewed. `TestSATTimeoutSealFailureRollsBackFinalModule` and `TestSATClassroomStaffRouteVsTerminalizationMySQL` (MySQL, `-race`). | High. PRINT-3 (`closed_server_frozen`) and SC-07 rest on it. |
| A-FAIR | The repair job runs repeatedly. Each run reaches every pending row within a bounded number of batches. | `background/runner.go` schedules `RepairClassroomResults`. The batch is ordered `updated_at, id` with a `LIMIT`. | Reviewed. Not soak-tested across instances. | Medium. LIVE-1 only. |
| A-OPT | Option ids are unique within a question. | The publish gate: `satpublish.validateChoiceAnswer` now rejects a repeated option id (`sat.choice.id.duplicate`), and the release screen lists it under "Answer choices". Drafts may still hold duplicates; only a published version is administered. | **Gap found and fixed** (see PROOF_REPORT). Before, nothing checked it, and a duplicate made two choices one answer for grading as well as for the paper. `TestValidateQuestionFlagsEachRequiredChoiceAndAnswerRule/duplicate_choice_id` and, end to end on MySQL, `TestSATPublishRejectsEachContentViolationMySQL/duplicate_choice_id` (`evidence/mysql-publish.txt`). A mutation removing the check fails both. Versions published before the check were not audited. | Medium. PAPER-1's "single circle" (`circle_exact` takes `opts.Nodup`). |
| A-PUB | Every administered SAT module has at least one operational question. | The SAT blueprint creates every module with a fixed target (27 RW, 22 Math; `exams/sat_initialization.go`); clones copy it and no code updates `target_question_count`. The publish transaction (`exams/service.go:929`, `satpublish.ValidateDraftForScope`) requires `len(questions) = target` and exactly 2 pretests for all three modules of each selected section. `operational_question_count` counts every non-pretest question of the module (`queryScoringRowsV2FirstTx` selects `FROM assessment_exam_questions … LEFT JOIN` responses), answered or not. So a published module has ≥ 20 operational questions. | Reviewed. `TestValidateModuleUsesConfiguredTarget`, `TestValidateModuleRequiresExactlyTwoPretests`, `TestValidateDraftRequiresAllThreeModulesInSelectedSection` (`satpublish/validator_test.go`). Versions published before this validator existed were not audited. | Medium. It makes L-1 unreachable for gated releases (LIVE-1). |
| A-PIN | The paper is rendered from the published version the attempt sat, not the current draft or a later release. | `Bootstrap` (`delivery/service.go:369`) loads sections by `exam_schedules.published_version_id`. The attempt pins `student_attempts.published_version_id` at creation (`CreateScheduleAttempt`, the only `student_attempts` insert). `schedules.Update` (the only writer of the schedule's version) refuses a version change once any attempt exists, in every start mode (`START_CODE_RELEASE_FROZEN`). The check holds the schedule row `FOR UPDATE`, which `CreateScheduleAttempt` also takes, so a join cannot race it. | **Bug found and fixed** (see PROOF_REPORT, "Fixed during this verification"). Before the fix the freeze applied only to code-start sessions: a proctor-start session reset to `scheduled` could be rebound, and completed students' papers showed the new version's questions against their old answers. `TestUpdateFreezesVersionOnceCandidatesJoined` (sqlmock; mutation to the old placement fails it). Authoring writes go to the draft version (e.g. `authoring/delivery_settings.go` bumps `draftID`). That a published version's content never changes was spot-checked, not exhaustively verified. | Medium. PDF-07. |
| A-SESS | The student bootstrap and its re-read are bound to the bearer's own attempt. A student cannot name another attempt id. | Delivery bootstrap handlers take `bearerScheduleID` / `bearerAttemptID` from the session. | Reviewed. Covered by the existing student-session authz suites, not re-run here. | High. PDF-08 for the client flow. |
| A-KEYLESS | The delivery projection sent to the student carries no answer key, so the paper cannot show a correct answer. | Delivery section projection (keyless student payload). `AnsweredExamPaper` takes no key input. | Reviewed. `marks the paper: chosen option circled…` asserts no correctness marking. | High. PDF-02. |
| A-NORM | `norm` is `ToLower(TrimSpace(·))`, and the stored release status is one of `pending` / `released` / `invalidated`. | `StudentResultScoreVisible` (`delivery/student_result_release.go:40`). | `TestStudentResultScoreVisible`. | Low. The client's exact `"released"` check fails closed under any other spelling. |
| A-RAW | The bootstrap that follows a seal reads its own committed write: one primary, no read replica on this path. | `delivery.Service.db` (single pool). | **UNKNOWN in production.** True in the tested topology. | Medium. If replicas are used, a freshly released report can be briefly invisible. That is a delay, not a wrong score. |
| A-DOM | A figure counts as loaded only if `img.complete && naturalWidth > 0`. The browser fires `load`/`error` for every `<img>`. | `answeredPaperReady` (`SatScoreReport.tsx:55`). | jsdom tests (`is ready only when every figure shows a decoded image`, `never prints when a figure cannot load`). No real-browser run. | Medium. PRINT-1's "all figures decoded". |

## Unknowns (recorded, not assumed)

| ID | Unknown | Why it matters | How to resolve |
| --- | --- | --- | --- |
| U-1 | Production instance count and how many `RepairClassroomResults` runners run concurrently. | The model allows any number of runners. Only a two-binary MySQL test was run (`TestSATClassroomStaffRouteAcrossAPIBinariesMySQL`). | Deployment manifest, plus a multi-instance soak (PRODUCTION_TEST_PLAN P-1). |
| U-2 | Production DB engine and isolation level. `cmd/migrate` names **MySQL 8.4** as the supported production engine; local evidence ran on **MySQL 9.6.0** at its default isolation. | Locking reads behave the same across these. Gap locks and deadlock profiles may differ. | Re-run `evidence/mysql-result-*.txt` on 8.4 with the production `transaction_isolation`. |
| U-3 | Browser print engines (Chrome/Safari/Firefox page breaks, KaTeX, images). | PDF-05 fidelity is outside the model. | Playwright print-to-PDF snapshots (P-4). |
| U-4 | Conversion table contents and calibration. | The global policy is wired into student and staff reads; the local integration test proves application of a published policy, not that its values are right. | Psychometric owner sign-off against an authoritative calibration source. |

## Known limitations

| ID | Limitation | Lean witness | Production reachability |
| --- | --- | --- | --- |
| L-1 | A module with zero operational questions withholds the report forever. `reportOf` requires a positive operational count, and repair never changes the row. | `ResultMachine.zero_op_never_released`, `zero_op_stuck` | **Unreachable** for releases that passed the publish gate (A-PUB). Reachable only for legacy versions published before the validator, or by direct DB edits. |
| L-2 | In the model, a later terminate invalidates a released result. | `ResultMachine.released_then_invalidated` | **Unreachable** under A-RCPT: a submitted receipt cannot be re-sealed as terminated. |
| L-3 | Turning the flag on later lets repair release older pending results. Turning it off hides already released reports. | `ResultMachine.flag_late_release`, `Release.flag_off_hides_released` | Reachable, and **intended**: `ScoreReportSettingPanel` says "a change applies to past attempts too". |
| L-4 (resolved) | Earlier report incorrectly said the exam flag alone controls release. The current gate requires both `sat_score_report_enabled` and `sat_session_mode = 'classroom'`; a Standard Practice sitting stays withheld even for a backfilled exam. | `ResultMachine.practice_never_released`, `step_classroom`; `results.SATScoreReportOpenSQL` | `TestSATPracticeSittingNeverReleasesWithReportOnMySQL` passed on local disposable MySQL 9.6.0. Production correspondence is reviewed, not mechanized. |
| L-5 | Duplicate option ids draw two circles. | `Paper.duplicate_ids_double_circle` | **Unreachable** for releases that passed the publish gate (A-OPT). Reachable only for legacy versions or direct DB edits. |
| L-6 | The client checks the literal `"released"`, while the server normalizes case and space. | `Release.client_gate` vs `Release.visible_only_released` | Fails closed: a non-canonical status shows no report. Not a leak. |
| L-7 | The staff question list is capped at 500 rows (`satQuestionsQ … LIMIT 500`, `results/service.go:1129`). | (not modeled) | Unreachable for SAT-sized exams (98 questions). Silent truncation above 500. |
| L-8 | A media failure outside a protected figure is detected only by the 30 s timeout. Ctrl+P outside the download flow prints whatever is mounted. | `PrintGate.poll_can_end` (the flow ends) | Reachable. It is a delay or a user-initiated print, never a gated print of an unready paper. |
| L-9 | The domain/skill breakdown is best-effort and not modeled. | none | Out of scope (SPEC exclusion). |
| L-10 | **Model-to-code gap for conversion (migration 0087).** `Convert.convertTopo_*` in this package models an older per-exam, 1D converter. The live estimate is resolved at read time against the global, versioned policy (`internal/satscoring`, `satconvert.Content.Resolve`): a matrix for full topologies and a one-dimensional table for standalone Module 2, with exact operational-count matching. `classroomRaw` raw fields remain the audit evidence; only `conversion`, `sections[].scaled/conversionStatus/topology` and `totalScaled` are overlaid. Go tests cover topology, dimensions, fail-closed behavior and retroactive display. The separate global Lean model proves its abstract lookup and publish/display properties but does not model Go topology assignment, total construction, or compose with this package's release gates. | `TestSATGlobalScoreConversionIsRetroactiveMySQL`, `TestOverlayNeverInventsAScore`, and `verification/lean/sat-score-conversion` | Publishing a revision changes the estimate shown for every released `classroomRaw` result, past and future. Raw scores and answers remain stored unchanged. The active production revision and the calibration accuracy of its values were not inspected in this test run. |
