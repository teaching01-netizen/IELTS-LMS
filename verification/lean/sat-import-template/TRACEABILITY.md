## Proof-to-code gap

The Lean model duplicates finite values and abstract predicates; it does not import Go constants or execute the Go generator. Go integration tests inspect bytes produced by the implementation and pass those bytes through Excelize and ParseSATWorkbook. This is useful refinement evidence but is not a mechanized simulation proof. Changes to module labels, taxonomy, validation ranges, parser aliases, or answer validation must update both the model and tests.
