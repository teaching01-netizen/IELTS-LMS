## Model-to-code refinement map

| Lean action/predicate | Code / database operation | Equivalence status and gap |
| --- | --- | --- |
| `.claim actor observedGeneration`; aggregate `pending + failedCurrentWindow ≤ 200` | `sat_start_code_guards` `SELECT ... FOR UPDATE`, expiry update/count, pending reservation insert in `reserveStartCodeComparison` | Same intended guard/capacity rule. Lean abstracts individual rows, SQL engine locking, concurrent query failures, and generation/window persistence. Table-level lock attribution is still needed. |
| `.settleMismatch`, `.settleSuccess`, `.expire`, `.rollWindow`, `.rotate` | Reservation settlement, sweeper, window accounting, and code rotation paths | Test-backed source correspondence; no mechanized SQL refinement. Crashes/settlement errors and worker redelivery remain partial. |
| `.beginWait`, `.wake`, `.timeout`, `.cancel` | Per-service per-schedule gate and wait loop | Go unit/race tests cover waiter cap, cancellation, timeout, cleanup. Wall-clock scheduling/fairness is not proved. |
| `activeStartWorkers ≤ startWorkerLimit` | `.acquireStartWorker`, `.releaseStartWorker`, crash/restart in `OperationalModel.transition` | `workerBound_transition` is proved for the abstract transition relation. Go uses `len(activeStartWorkers) < cap(activeStartWorkers)`; the proof does not establish semaphore initialization from DB pool configuration or runtime scheduling. |
| `.commitColdRuntime`, `.remoteRuntimeCommit`, `.staleExclusiveRollback`, `.retrySharedRuntime` | Local initializer gate plus schedule `FOR UPDATE` recheck and shared-path retry in `codeStartTx` | MySQL same-process and two-service cold races exercised. No multi-host deployment test or code-generation refinement proof. |
| `commitFirstStart` / `startIfEligible` | Transaction updates acceptance/generation, module activation/deadline, runtime plan, audit | Abstract atomic state update matches the intended transaction result. Lean does not establish the Go SQL statements execute as one durable atomic commit. |
| `canResume` / `resumeIfStarted` | `resumeCodeStart` plus authoritative bootstrap read | Model preserves the entire abstract world. Database recovery behavior is integration-tested, not mechanized. |
| `firstStartEligible` ownership/version/window/scope fields | Token claims, transaction checks, current code/window reads, selected module ownership/scope SQL | Predicate-to-SQL is reviewed and tested. There is no formal parser/authentication or SQL refinement relation. |
