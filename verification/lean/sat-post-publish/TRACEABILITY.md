## Follow-up obligations and evidence

- `Provenance.lean` records the operational model's accepted commit steps. `acknowledged_receipt_has_commit` derives membership in this history for every reachable tracked receipt, strengthening the original exam-ID-only invariant. `tracked_step_refines_client_step` proves erasure of ghost history gives the existing Lean step; this is a relation between Lean models, not a TypeScript refinement proof. `tracked_success_is_reachable` supplies a success witness for every target, avoiding vacuity.
- R5 now has a parent-level regression showing stale published-version metadata cannot hide a failed shell read. A locally acknowledged publication may still show its completion independently of failed refreshes; forbidden and missing-exam states remain distinct.
- R6 now has a deterministic parent regression: remove the shell while the legacy draft has pending work, then export the retained question payload and observe copy feedback without a save/flush. Device and collaborative export recovery surfaces are also rendered through the no-shell boundary. This is PARTIAL correspondence evidence; it does not replace the two-real-context collaborative publication scenario or establish R6 formally.
- Retained-key publication replay, revision fences, and three concurrent-open scenarios passed on a freshly migrated isolated local MySQL 9.6.0 instance. N=20 concurrent published/no-draft openers returned one cloned draft with the source intact. This validates the stated local compatibility profile, not crash recovery, multiple API processes, or the production MySQL version/configuration.
