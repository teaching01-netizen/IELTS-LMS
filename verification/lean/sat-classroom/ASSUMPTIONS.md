## Model assumptions

The Lean state starts empty with a valid policy/plan and represents one section with arbitrarily indexed attempts. It treats a step (including a close and its snapshot, or a database fence check) atomically. It does not model persisted malformed startup states, partial migration states, separate SQL reads/writes, transaction aborts, crashes, acknowledgments, retries as network histories, multiple sections in a single completion gate, clocks, database failover, or the actual score payload. These are proof boundaries, not facts established about production.
